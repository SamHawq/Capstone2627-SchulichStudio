# Inspect survey keyword extraction

`src/hiring_agents/textagent.py` is a standalone OpenAI Agents SDK agent. It
extracts keywords only and does not call the orchestrator or any ranker.

Run these commands from the repository root. Create an isolated Python 3.12
environment first (on this Mac, Python 3.12 is at `/usr/local/bin/python3.12`):

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-textagent.txt
```

Install **`openai-agents`**, not `agents`. Both expose the import name `agents`,
but the latter is an unrelated TensorFlow reinforcement learning package.
In the Anaconda base environment on this Mac, importing it aborts Python with
an AVX error. The isolated environment avoids that package and leaves base intact.
Keep these packages in separate environments. Activate `.venv` in each new terminal,
or use `.venv/bin/python` explicitly.

The standalone dependencies are pinned in `requirements-textagent.txt`.
In particular, `openai-agents==0.8.4` uses `openai==2.19.0`: allowing the newer
`openai==2.54.0` causes a `cache_write_tokens` validation error while initializing
the runner, before any API call. To repair an existing venv, activate it and run
the install command above. The broader application's `requirements.txt` is
separate from this standalone setup.
Validate the CSV without model calls:

```bash
python src/hiring_agents/textagent.py --validate-only
```

Set `OPENAI_API_KEY` in your shell, `.env`, or `environment_vars.env`. Optionally
set `OPENAI_MODEL` to a structured-output-capable model available to your account.
An explicit `--model` overrides that setting; otherwise the SDK default applies.
Start with two candidates:

```bash
python src/hiring_agents/textagent.py --limit 2 --output keywords-preview.json
```

Omit `--limit` to process everyone. Use a new output filename for each run;
existing files are not overwritten. JSON is printed to stdout and progress to
stderr. A failed extraction raises an error rather than writing an empty result.

The default path points to the original survey in `sample_datacsv` relative to
the script, so the command also works from another working directory. To use
your saved filtered CSV instead:

```bash
python src/hiring_agents/textagent.py filtered_candidates.csv --output keywords.json
```

Filtered input must contain `student_id` or `reference_id` and these four fields:
`technical_skills`, `communication_skills`, `engaged_learning`,
`active_learning_example`. The original survey's combined skills/technical
knowledge question stays one category. Original survey headings and its two
header rows are checked before reading columns 0, 8, 9, 10, and 18.

Illustrative output (not extracted from real applicants):

```json
{
  "00123": {
    "technical_skills": ["Python", "Cannot use MATLAB"],
    "communication_skills": ["Explaining concepts using diagrams"],
    "engaged_learning": [],
    "active_learning_example": ["Think-pair-share"]
  }
}
```

IDs are preserved as strings and attached by Python, not generated by the model.
Each nonblank candidate gets a separate model run containing only their four
responses. Blank candidates remain in the output with four empty lists. Blank
categories are forced to empty lists and terms are deduplicated within each
category. The extraction instructions preserve uncertainty and negation and
prohibit scores or hiring recommendations. SDK tracing is disabled for these runs.

Structured output validates the shape, not the truth of extracted phrases.
Compare a small output sample with the source responses, especially negation,
claimed versus demonstrated experience, and category boundaries. Personal
information inside free-text responses is not automatically redacted before the
model call. Generated JSON preserves candidate IDs; keep it with applicant data.

Offline contract tests (no API key or model requests):

```bash
python -m unittest tests.test_textagent
```

These include a real SDK runner with a simulated model response, so token-usage
initialization and structured-output parsing are checked without API calls.
